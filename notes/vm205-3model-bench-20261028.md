# VM205: Qwen3.8-Flash-Next vs DeepSeek-V4.1-Flash vs GLM-5.3, measured 2026-10-27/28

Same host, same prompts, same grading for all three so the numbers can be compared. Every
value here is measured on VM205; none is a vendor claim.

## Configurations

| arm | model id | runtime | context | weights |
|---|---|---|---|---|
| Qwen | `orcarouter-qwen3.8-flash-next-uncensored-q4_k_m` | Strata 0.2.2 image, `serve.server --engine strata` | 524288 | OrcaRouter uncensored Q4_K_M pack (112 GB) |
| DeepSeek | `deepseek-v4.1-flash` | Strata 0.2.7, engine 0.1.52, `dsv41` | 262144 | IST-DAS 2.25bpw (IQ2_XS 155 GB) + Engram 111 GB + DSpark 8 GB |
| GLM | `glm-5.3-flash` | Project Maya v1.1.31 (`c4be544`), engine built for sm_89 | 262144 | Maya-M-Derisked IQ2_S (109 GiB) + DFlash2 drafter |

Host: Proxmox guest VM205, Ubuntu 26.04, NVIDIA driver 595.84, RTX 4090 24 GB, 215 GB RAM,
Ryzen Threadripper 7970X (32 vCPU). One engine owns the GPU at a time.

DeepSeek full-residency (Strata 0.2.6+) came on by itself: 13,893 CPU-lane experts (134.8 GB)
copied into RAM in 58.5 s, no demand store, 23,570 MiB of VRAM in use afterwards.

GLM speed calibration picked DFlash2 drafting: 39.9 vs 34.1 tok/s without it (+17%), 91% of
drafts accepted, so the start script enables it.

## Speed (the engines' own timings)

| metric | Qwen(Orca) | DeepSeek 2.25 | GLM Maya-M |
|---|---|---|---|
| decode, median of 3, thinking off | **67.4 tok/s** | 47.6 tok/s | 39.2 tok/s |
| decode, default thinking, 64 tokens | not measured | 41.9 tok/s | 48.3 tok/s |
| prompt 4K | 1301 tok/s | 854 tok/s | **1866 tok/s** |
| prompt 16K | not measured | 1607 tok/s | **2512 tok/s** |

Raw decode runs: Qwen 65.9 / 74.4 / 67.4; DeepSeek 30.6 / 47.6 / 53.4 (first run cold);
GLM 31.2 / 39.2 / 45.7. Prefill for DeepSeek was 854 tok/s at 4K and 1607 at 16K, so its 4K
number is the weakest of the three.

## Capability (lm-eval, `--limit 100`, `--apply_chat_template`, thinking left at each model's default)

| metric | Qwen(Orca) | DeepSeek 2.25 | GLM Maya-M |
|---|---|---|---|
| gsm8k strict-match | 0.53 | 0.00 (format) | **0.94** |
| gsm8k flexible-extract | 0.57 | 0.93 | **0.94** |
| ifeval prompt-level strict | **0.84** | 0.81 | 0.72 |
| ifeval instruction-level strict | **0.890** | 0.877 | 0.81 |
| ifeval prompt-level loose | **0.85** | 0.80 | 0.79 |

DeepSeek's strict 0 is a scoring artifact: it writes its reasoning first and does not end the
answer with `#### <number>`, which the strict GSM8K matcher requires; flexible extraction finds
the right value 93% of the time. The Qwen run also logged several empty `content` responses,
so its 0.57 is more likely an underestimate than an overestimate.

## Sanity fixtures (Strata `bench/prompts/standard-v1`, 12 cases, machine-graded)

| arm | passed |
|---|---|
| DeepSeek 2.25 | 12/12 |
| GLM Maya-M | 12/12 |
| Qwen(Orca) | not run (the old container had to stay stopped) |

The four instruction cases (JSON shapes), four retrieval cases (token recall) and four tool
cases (OpenAI `tool_calls` with correct argument types, including a `string="true"` value) all pass
on both models that were tested.

## Caveats

- n=100, single run. stderr is about ±0.02-0.05 on gsm8k and ±0.04 on ifeval, so the ifeval gaps
  between 0.84 / 0.81 / 0.72 are close to noise except perhaps the GLM one.
- Thinking defaults differ (Qwen effectively off, DeepSeek on, GLM `high` with a 32768 budget), so
  generation lengths are not matched. A strict comparison needs `reasoning_effort: "none"` on all
  three.
- Context differs: Qwen ran at 524288, the other two at 262144.

## Pitfalls hit during the run

1. **Strata's model downloader stalls at the end of each file.** On every shard the last ~3
   chunks (one per parallel connection) stay `ESTAB` with no data and the transfer never
   finishes. `docker restart` resumes from `<file>.part.chunks`; a watchdog that restarts after
   90 s without growth worked, but it must watch the whole `models/` tree because the Engram
   lands in `deepseek-v4.1-flash-shared/`, not beside the shards. Watching only the model
   directory restarts a healthy download.
2. **The shared `/data` preset carries old engine flags.** The `docker` preset saved by the 0.2.2
   Qwen setup contains `--resident-budget-gib` / `--vram-reserve-mib`, which `strata-dsv41`
   rejects with `unknown option` and exits 1 after a successful load. Start DeepSeek with a
   fresh `PRESET` name.
3. **Project Maya's release tags are annotated.** `git ls-remote --tags` returns the tag object,
   and the Dockerfile's `test "$(git rev-parse HEAD)" = "$MAYA_COMMIT"` then fails. Use the
   peeled commit from `refs/tags/vX^{}` (v1.1.31 = `c4be54416a4f30a837c2fae91816dc9550d68b61`).
4. Maya v1.1.0 → v1.1.31 needed no Dockerfile change: `setup.PY_PACKAGES`, `pip_install`,
   `get_llama_cpp`, `source_hash`, `ENGINE_SOURCES`, `maya.compile_engine` and `toolchain_for`
   kept their names and signatures.

## Reproduce

```bash
# speed + the 12 fixtures, any OpenAI-compatible endpoint
python3 bench_openai.py --base-url http://100.0.0.159:8080/v1 \
  --model deepseek-v4.1-flash --key-env BENCH_API_KEY --label deepseek-2.25-256k

# capability, same flags for every arm
lm_eval run --model openai-chat-completions \
  --model_args model=<served-id>,base_url=http://100.0.0.159:8080/v1/chat/completions,tokenizer_backend=None \
  --tasks ifeval,gsm8k --limit 100 --apply_chat_template \
  --output_path results.json
```
